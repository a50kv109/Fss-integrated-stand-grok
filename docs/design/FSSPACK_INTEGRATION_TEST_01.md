## 1. Цель испытания

Проверка сквозного контура переносимого объекта кристаллографической симметрии (`.fsspack`):
1. **Экспорт:** Стенд A формирует стандартизированный `.fsspack` пакет через `PackageExporter` и эндпоинт `/api/fsspack/export/:settingId`.
2. **Транспорт:** Загрузка `.fsspack` архива в пользовательский интерфейс (UI) через кнопку «Импортный паспорт» («Import Passport») или скачивание «Образец P41» («Sample P41»).
3. **Приемка (Gatekeeper):** Стенд B принимает архив через эндпоинт `/api/fsspack/ingest` и пропускает его через 6-ступенчатый контур верификации (`ZipContainer`, структура, целостность SHA-256, совместимость версий, независимая проверка математических аксиом группы).
4. **Отображение в UI:** Корректное отображение в модальном окне статуса приемки (`VERIFIED_ACTIVE`), этапов проверки, манифеста, математической модели и происхождения данных (provenance).

## 2. Фактически проверенные сценарии и результаты

Автоматизированный интеграционный тест-раннер (`tools/fsspack-prototype/integration_test_runner.ts`) и модульные тесты (`prototype.test.ts`, `hardening_01.test.ts`) выполнили следующие реальные сценарии:

1. **GET `/api/fsspack/export/P41`:**
   - *Результат:* Успешно сформирован валидный ZIP-архив для пространственной группы № 76 ($P4_1$, settingId `P41`), возвращен с заголовком `application/zip` и именем файла `P41.fsspack`.
2. **POST `/api/fsspack/ingest` (Валидный пакет):**
   - *Результат:* Успешное прохождение всех 6 этапов Gatekeeper. Статус приемки: `VERIFIED_ACTIVE`. Математическая модель ($4_1$ винтовая ось, 4 операции, точные рациональные трансляции $[0, 0, 1/4]$, центр ячейки) подтверждена независимо.
3. **Негативный тест — Поврежденный ZIP-контейнер (Stage 1):**
   - *Результат:* Передача случайного бинарного буфера вместо ZIP корректно отсечена на Этапе 1. Статус: `REJECTED` с ошибкой `CORRUPT_ZIP_CONTAINER`.
4. **Негативный тест — Отсутствие обязательного файла (Stage 2):**
   - *Результат:* Архив без `manifest.json` отсечен на Этапе 2. Статус: `REJECTED` с ошибкой `MISSING_MANDATORY_FILE`.
5. **Негативный тест — Подделка контрольной суммы / Tampered Checksum (Stage 3):**
   - *Результат:* Модификация `math-model.json` без обновления манифеста обнаружена на Этапе 3 по несовпадению SHA-256 хэша. Статус: `REJECTED`.
6. **Негативный тест — Неподдерживаемая версия схемы (Stage 4):**
   - *Результат:* Указание версии `fsspackVersion: "99.0"` заблокировано на Этапе 4. Статус: `REJECTED`.
7. **Негативный тест — Математически некорректная модель (Stage 5):**
   - *Результат:* Подмена матриц симметрии $W$ на недопустимые (нарушение детерминанта или замыкания группы) выявлена на Этапе 5 независимым пересчётом групповых таблиц. Статус: `REJECTED`.

## 4. Обнаруженные дефекты и внесённые исправления

1. **Несоответствие ключей версии в тестах:**
   - *Проблема:* В тесте проверки версии на Этапе 4 проверялся несуществующий ключ `manifest.specVersion` вместо специфицированного в контракте `manifest.fsspackVersion`.
   - *Исправление:* Ключ в тестовой симуляции был скорректирован на `fsspackVersion`.
2. **Валидация Stand A при экспорте мутированных моделей:**
   - *Проблема:* Прямой вызов `PackageExporter.export()` для тестирования Stage 5 отторгал математически некорректные группы ещё на этапе экспорта (что корректно для Stand A, но мешало симуляции приёма поврежденного пакета от внешнего злоумышленника на Стенде B).
   - *Исправление:* Интеграционный тест был переписан так, чтобы обходить Stand A экспортер для генерации зловредного пакета и напрямую формировать ZIP через `ZipContainer.pack()` с обновлением хэша в `manifest.json`, проверяя именно защитные барьеры Gatekeeper Стенда B.
